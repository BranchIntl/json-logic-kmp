# Agent notes

[README.md](README.md) is the library, [CONTRIBUTING.md](CONTRIBUTING.md) is how to build and test
it, and [PUBLISHING.md](PUBLISHING.md) is how a release is cut. What follows is only what those
files do not say: the things that have cost someone an afternoon and are written down nowhere else.

## Toolchain traps

- The local default JDK is Temurin 17; CI runs 21. Neither is the target: `lib/build.gradle.kts`
  pins `jvmTarget = JVM_11`, so the difference between the two is in the toolchain, not in what it
  emits.
- Any Gradle task that links or runs an iOS test binary — `:lib:iosSimulatorArm64Test`,
  `linkDebugTestIosSimulatorArm64` — needs `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`
  in front of it, because `xcode-select` points at CommandLineTools. Compiling the main klibs does
  not need it, which is why `:lib:assemble` and `:lib:apiDump` work without it. Without the prefix
  nothing in the failure names Xcode: Gradle reports `An error occurred during an xcrun execution`
  against `/usr/bin/xcrun xcodebuild -version`, a command that on its own exits 72.
- The Android SDK is found through `sdk.dir` in `local.properties`, which is gitignored, and
  `ANDROID_HOME` is usually unset. A fresh worktree therefore starts with no way to find the SDK and
  needs a `local.properties` of its own before any Android task will run.
- Never run the iOS simulator test lane in two worktrees at once: `simctl` flakes when two runs
  reach for a simulator together.

## Repo invariants

- `:lib` is the published library. `:playground` is a demo that publishes nothing and is excluded
  from binary-compatibility validation through `apiValidation { ignoredProjects }` in the root
  build.
- `:playground` compiles `lib/src/commonMain/kotlin` as a source directory of its own rather than
  resolving a publication. A library change can therefore break the playground lane without any file
  under `playground/` changing, and it is the only lane that builds the library for a browser.
- `commonTest`'s fixture corpus is generated by the `generateFixtures` Gradle task, into
  `build/generated/`. Never hand-edit the generated file — change the JSON under
  `lib/fixtures/` and let the task run.
- The public API is locked by binary-compatibility-validator across both the JVM and KLib surfaces,
  with the dumps committed under `lib/api/`. Any change to the public API has to regenerate them
  with `./gradlew :lib:apiDump` (which collects `jvmApiDump` and `klibApiDump`) and commit the
  result in the same change, or `:lib:apiCheck` and `:lib:klibApiCheck` fail in CI.

## Conventions

- `CHANGELOG.md` keeps a standing empty `## [Unreleased]` heading, so a change always has somewhere
  to land without deciding a version number for it. A release renames that heading to the version
  and its date, and opens a fresh empty one above.
- Publishing fires only on `workflow_dispatch`, and only against `main`; see
  [PUBLISHING.md](PUBLISHING.md).

## Checking your work locally

These are the four CI lanes, in the order [CI lanes](CONTRIBUTING.md#ci-lanes) lists them:

```bash
./gradlew :lib:jvmTest :lib:testAndroidHostTest :lib:assemble :lib:apiCheck
./gradlew :lib:wasmJsNodeTest
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer ./gradlew :lib:iosSimulatorArm64Test :lib:klibApiCheck
./gradlew :playground:jsBrowserTest :playground:jsBrowserDistribution
```

The third is the only one that needs the prefix, and the only one that must not be running in
another worktree at the same time.
